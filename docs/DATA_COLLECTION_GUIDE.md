# Ground-Truth Data Collection Guide

## Why This Exists

The accuracy reported in `results/best_model_metrics.json` (76.9% in the current revision, previously cited as 97.97%) is **circular** — the
labels in `data/processed/dataset_final.csv` were auto-generated by the same threshold function
(`risk_from_features()` in `backend/services/features.py`) that the classifier is trying to learn.
No human expert has ever verified whether any of the 5,920 samples are actually LOW, MEDIUM,
or HIGH.

This guide covers how to produce the **first honest, evidence-based accuracy number** for both
risk classification and task recognition, and optionally retrain on real labels.

---

## Phase 1: Recording

### Camera Setup

| Parameter | Value |
|---|---|
| Resolution | 1280 × 720 (720p) |
| Framerate | 30 FPS |
| Camera position | **Front-facing, ~1.5 m distance, centered** at chest height |
| Lighting | Bright indoor office (overhead + desk lamp) |
| Background | Plain wall, no clutter |

**Why these values?** This matches the only configuration the system has ever been tested under
(see `pose_estimation_status.md`). Changing multiple variables at once makes it impossible to
tell which change caused accuracy differences. After baseline is established, lighting and angle
can be varied deliberately.

### Subject Requirements

- **Minimum 3 subjects** with visibly different body shapes
  - Current testing is 1 person (the developer). Single-subject accuracy is not generalisable.
- Mix of fitted and loose clothing
  - MediaPipe Lite struggles with dark or reflective fabrics (`pose_estimation_status.md`).
- At least 1 subject repeats 2 scenarios on a different day
  - For inter-rater reliability / temporal stability check.

### Recording Procedure

The pipeline already records everything needed — no new code required.

1. **Start the backend:**
   ```
   cd backend_api
   python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```

2. **Login and start a session for each scenario:**
   ```bash
   # Login
   TOKEN=$(curl -s http://127.0.0.1:8000/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email":"admin@example.local","password":"AdminPass123!"}' \
     | python -c "import sys,json; print(json.load(sys.stdin)['token'])")

   # Start session — assign a unique worker_id per scenario
   curl -s -X POST http://127.0.0.1:8000/api/session/start \
     -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"worker_id":"data-collection-01","camera_index":0}'
   ```

3. **Record 2–4 minutes** of the subject performing the scenario activity.

4. **Stop the session:**
   ```bash
   curl -s -X POST http://127.0.0.1:8000/api/session/stop \
     -H "Authorization: Bearer $TOKEN"
   ```

5. **Collect the output from `recordings/data-collection-*/`:**

   | File | Content | Used for |
   |---|---|---|
   | `original.mp4` | Raw H.264 camera feed | Visual reference for human annotator |
   | `timeline.json` | Per-frame: risk_score, features, task, alerts | Model predictions to compare against labels |
   | `summary.json` | Aggregated session stats | Session-level metadata |

### Scenarios to Record

Record **each scenario once per subject** (30 recordings total for 3 subjects × 10 scenarios).

| # | Scenario | Target task class | Target risk | What the subject does |
|---|---|---|---|---|
| 1 | Upright standing | Neutral Standing | LOW | Stand still, arms at sides, looking forward. 2 min |
| 2 | Desk typing | Neutral Standing | LOW | Sit or stand at a desk, type on a keyboard naturally. 3 min |
| 3 | Overhead reaching | Reaching | MEDIUM | Repeatedly reach for objects on a shelf above shoulder height, alternating hands. 3 min |
| 4 | Extended forward reach | Reaching | HIGH | Reach for objects far forward (arms fully extended), hold each for 5–10 s. 3 min |
| 5 | Table assembly | Assembly Work | MEDIUM | Assemble small parts on a table (screws, blocks). Moderate forward lean, elbows bent. 4 min |
| 6 | Floor lifting | Lifting / Picking | HIGH | Pick up boxes/objects from the floor, straighten, place on a table. Repeat. 3 min |
| 7 | Eye-level inspection | Inspection | MEDIUM | Inspect objects held at eye level, tilting head. 3 min |
| 8 | Mixed workflow | All | Mixed | Natural sequence: stand → reach → lift → inspect → return to standing. 4 min |
| 9 | Slouching at desk | Neutral Standing | MEDIUM | Sit with forward head posture, rounded shoulders. 2 min |
| 10 | Low-light / side angle | Any | Unknown | Repeat scenario 5 with dimmer lighting or subject at a 45° angle to camera. 2 min |

## Phase 2: Labeling

Two **independent** labeling passes are needed. They serve different purposes and require
different expertise.

### Pass A — Risk Labels (LOW / MEDIUM / HIGH)

**Requires:** Someone with basic ergonomics awareness (can identify forward head posture,
rounded shoulders, trunk bending, etc.). An ergonomist or physiotherapist is ideal.

**Target:** ~500 labeled frames per class (1,500 total), stratified across subjects and scenarios.

**What to label:** For each frame, assign one of:
- **LOW** — Neutral posture. Head aligned over shoulders, shoulders relaxed, trunk upright,
  arms within 20° of vertical.
- **MEDIUM** — Notable deviation. Head forward >10°, shoulders elevated, trunk leaned forward
  20–60°, arms raised 30–60°, or knees bent 100–150°.
- **HIGH** — Extreme deviation. Head forward >30°, trunk >60°, arms >60°, knees <100°,
  or any asymmetric loading.

**Labeling tool options:**

| Tool | Setup time | Pros | Cons |
|---|---|---|---|
| **Custom Python frame-player** | ~2 hours dev | Fastest per-frame workflow; outputs JSON directly | Needs to be written |
| **VIA (VGG Image Annotator)** | 30 min | Browser-based, free, export to CSV/JSON | Needs frames extracted from video as PNGs |
| **CVAT** | 1 hour (Docker) | Supports video directly, multi-user, free | Overkill for 3-class; server must stay running |

**Recommended approach:** A lightweight Python script (`scripts/label_frames.py`) — **implemented as of 2026-08-12** — that:
1. Opens `original.mp4` with OpenCV
2. Shows each frame (or every Nth frame for sparse labeling)
3. Waits for keypress: `1` = LOW, `2` = MEDIUM, `3` = HIGH, `Space` = pause, `Left/Right` = skip
4. Saves `ground_truth_risk.json` with format (the script also supports the task pass via `--kind task`):
   ```json
   {
     "session_id": "SESH-...",
     "labeler": "annotator_name",
     "date": "2026-07-25",
     "frames": [
       {"frame": 0, "label": "LOW"},
       {"frame": 30, "label": "LOW"},
       {"frame": 60, "label": "MEDIUM"},
       ...
     ]
   }
   ```

### Pass B — Task Labels (5 classes + Unknown)

**Requires:** Anyone familiar with what the tasks look like. No special training needed.

**Target:** ~200 frames per task class (1,000 total).

**Classes:**
- `Neutral Standing`
- `Assembly Work`
- `Reaching`
- `Lifting / Picking`
- `Inspection`
- `Unknown` (for ambiguous frames)

**Same tooling as Pass A** but with keys mapped to task names instead of risk levels.

## Phase 3: Evaluation Script

Once labels exist, a script (`scripts/evaluate_ground_truth.py`) will:

```python
import json
import pandas as pd
from sklearn.metrics import accuracy_score, classification_report, confusion_matrix

# Load ground-truth labels
with open("ground_truth_risk.json") as f:
    gt = json.load(f)
gt_df = pd.DataFrame(gt["frames"])

# Load model predictions from timeline.json
with open("recordings/.../timeline.json") as f:
    timeline = json.load(f)
pred_df = pd.DataFrame(timeline)  # has risk_score, task per frame

# Merge on frame number
merged = gt_df.merge(pred_df, on="frame", how="inner")

# --- Risk classification metrics ---
y_true = merged["label"]
y_pred = merged["predicted_risk"]  # derived from risk_score thresholds

print("=== RISK CLASSIFICATION ===")
print(f"Accuracy: {accuracy_score(y_true, y_pred):.4f}")
print(classification_report(y_true, y_pred))
print(confusion_matrix(y_true, y_pred))

# --- Task recognition metrics ---
y_true_task = merged["task_label"]   # from ground_truth_task.json
y_pred_task = merged["task_name"]    # from timeline.json

print("\n=== TASK RECOGNITION ===")
print(f"Accuracy: {accuracy_score(y_true_task, y_pred_task):.4f}")
print(classification_report(y_true_task, y_pred_task))
```

## Phase 4: Optional — Retrain / Improve

If the real accuracy is below target, the new labels enable:

1. **Retrain risk classifier** via existing `scripts/train_svm.py` — replace the auto-labeled
   `dataset_final.csv` with the human-labeled dataset.
2. **Tune task recognition Gaussians** — the hand-tuned means/sigmas in
   `backend/services/task_recognition.py` can now be optimised against real data.
3. **Add to regression suite** — include the labeled recordings in CI so future changes
   don't regress accuracy without detection.

## Estimated Effort

| Phase | Time | Dependencies |
|---|---|---|
| Phase 1: Recording (10 scenarios × 3 subjects) | 2–3 hours | Camera, subjects, backend running |
| Phase 2 Tooling: `scripts/label_frames.py` | 2 hours | None (developer) |
| Phase 2 Pass A: Risk labeling (~1,500 frames) | 4–8 hours | Ergonomics-aware labeler |
| Phase 2 Pass B: Task labeling (~1,000 frames) | 2–3 hours | Any labeler |
| Phase 3: Evaluation script + metrics | 2–3 hours | Labeled data must exist |
| Phase 4: Retraining (optional) | 2–4 hours | Labeled data must exist |
| **Total** | **12–19 hours** | **Blocked on ergonomics labeler for risk metrics** |

Note: Task recognition metrics do NOT require an ergonomics labeler — any annotator can assign
task classes. If risk labeling is blocked, task evaluation can proceed independently.
